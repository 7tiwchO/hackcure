## 2. Mobile Architecture & Conflicting/Duplicate Files

### Active Application Path
- **Mobile Root**: `mobile/`
- **Package Manifest**: `mobile/package.json` with `"main": "expo-router/entry"`.
- **Router Root**: `mobile/app/` — file-based routing directory (`_layout.tsx`, `index.tsx`, `(auth)/`, `(tabs)/`, `treatment/`, `prescription/`, etc.).
- **Application Source**: `mobile/src/` — all features, reusable components, theme, i18n, services, and hooks.

### Redundant / Conflicting Files Detected
1. **`mobile/App.tsx`**:
   - *Status*: **Conflicting/Dead Code**.
   - *Detail*: Default placeholder generated by `create-expo-app`. Because `package.json` specifies `"main": "expo-router/entry"`, Expo uses `mobile/app/` and ignores `mobile/App.tsx`. Leftover file can cause developer confusion.
2. **`mobile/scaffold_dirs.js`**:
   - *Status*: **One-off setup script**.
   - *Detail*: Node.js script used during initial directory creation. Not needed in production.
3. **`backend/finish_setup.py`**:
   - *Status*: **One-off setup script**.
   - *Detail*: Hardcoded Python script that originally generated initial schemas and routes. Superseded by real code in `backend/app/`.
4. **`backend/docker-compose.yml` & `backend/Dockerfile`**:
   - *Status*: Located in `backend/` rather than root. Configured for PostgreSQL + backend container. Local development runs SQLite with `check_same_thread=False` via `aiosqlite`.

## 3. Backend Architecture

- **Framework**: FastAPI (async) with Pydantic v2.
- **Entry Point**: `backend/app/main.py` (`app = FastAPI(...)`).
- **Database Engine**: SQLAlchemy 2.0 with async engine (`sqlite+aiosqlite:///hackcure.db` for local dev; `postgresql+asyncpg` for Docker/production).
- **Security**: JWT authentication (`app/core/security.py`), bcrypt password hashing, patient-level data tenancy verification.
- **Automation Endpoints**:
  - `POST /api/automation/report`: Draft creation for doctor report extraction.
  - `POST /api/automation/prescription`: Draft creation for prescription extraction.
  - `GET /api/automation/drafts/{patient_id}`: Draft retrieval with confidence scores.
  - `POST /api/automation/apply`: Atomic application of drafts (archives old, creates new, regenerates doses).
  - `GET /api/v1/patients/me/treatment-summary`: Current active treatment summary for authenticated patient.
  - `GET /api/v1/patients/me/doses/history`: Historical dose logs (taken, late, missed).
  - `GET /api/v1/patients/me/automation/drafts` & `POST /api/v1/patients/me/automation/apply`: Authenticated patient draft review and apply.

## 4. n8n Automation Architecture

- **Primary Workflow**: `n8n/hackcure-document-extraction-workflow.json`
  - Dual document webhook accepting both Doctor's Report + Prescription.
  - Vision/LLM extraction node with strict JSON schema and confidence scoring.
  - Draft creation via backend automation endpoints.
  - Review and atomic apply triggers.
- **Adherence Workflows**:
  - `hackcure-medication-adherence-workflow.json`
  - Daily check-in, escalation, and weekly summaries.

## 5. Physical Device Compatibility (Expo Go)

- Expo Go on Android SDK 53+ removed the native module for push notifications (`ExpoTopicSubscriptionModule`).
- The mobile codebase is configured with defensive loading in `useNotifications.ts` to ensure Expo Go runs with zero native runtime crashes, while preserving full notification scheduling in standalone/development builds.
